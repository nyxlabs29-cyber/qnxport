## QNX008

**CPU affinity** (category `process`, base severity `high`, documented in QNX 8.0 docs)

- **Why it matters:** sched_setaffinity / pthread_setaffinity_np and the CPU_* macros have no page in the QNX 8.0 C Library Reference.
- **QNX 8.0 strategy:** For the calling thread use ThreadCtl(_NTO_TCTL_RUNMASK, &mask) (also _NTO_TCTL_RUNMASK_GET_AND_SET and _NTO_TCTL_RUNMASK_GET_AND_SET_INHERIT); map CPU numbers to bits of the runmask. The ThreadCtl() page says the runmask commands can only be executed on the calling thread, so code that sets the affinity of ANOTHER thread or process (sched_setaffinity(pid, ...)) has no documented equivalent: the target thread must set its own runmask (verify). sched_getcpu() has no documented equivalent: verify.
- **QNX 8.0 docs:** [ThreadCtl()](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.lib_ref/topic/t/threadctl.html)

## QNX013

**/proc paths (Linux layout)** (category `system`, base severity `high`, VERIFY on your SDP)

- **Why it matters:** QNX has a /proc, but it is a process-manager namespace with its own layout, not Linux text files such as /proc/cpuinfo, /proc/meminfo, /proc/stat or /proc/<pid>/stat.
- **QNX 8.0 strategy:** Use the QNX /proc interface (devctl() with DCMD_PROC_* commands) described in the Programmer's Guide, sysconf(), or pidin-style queries instead of parsing Linux files. For the executable path, QNX provides /proc/self/exefile (verify on your target).
- **QNX 8.0 docs:** [Controlling processes via the /proc filesystem (Programmer's Guide)](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.prog/topic/process_proc_filesystem.html); [devctl()](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.lib_ref/topic/d/devctl.html)

## QNX019

**Linux/glibc preprocessor guards** (category `portability`, base severity `medium`, VERIFY on your SDP)

- **Why it matters:** Code under #ifdef __linux__ / __GLIBC__ is not compiled by qcc for QNX, so such branches silently disappear and some #else branches may pick a BSD or generic path that was never tested on QNX.
- **QNX 8.0 strategy:** Add an explicit __QNXNTO__ (and/or __QNX__) branch, or restructure so the portable code path is the default. qcc predefines the QNX macros: confirm with 'qcc -V... -dM -E - < /dev/null' on your SDP (verify).
- **QNX 8.0 docs:** [qcc / q++ (Utilities Reference)](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/q/qcc.html)

## Method and limitations

qnxport is a static, pattern-based scan (comments and string literals are understood; no compiler or preprocessor run). It lists the places that need attention and a porting strategy backed by the public QNX 8.0 documentation. It cannot prove that a project builds or behaves correctly on QNX: compile with qcc, run on a QNX 8.0 target and test. Findings marked 'verify' name a likely strategy that could not be confirmed from the public documentation; check them against the headers and docs of your installed QNX SDP. 'Not in the QNX 8.0 C Library Reference' means no page was found for the function, not that the symbol is absent from your SDP.
