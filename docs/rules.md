# qnxport rules

QNX 8.0 documentation cross-checked on 2026-11-06. Confidence `documented` = the QNX 8.0 docs page for the replacement exists and states the behaviour used; `verify` = likely strategy, confirm on your SDP.

| ID | Sev | Confidence | Category | Detects / strategy |
|---|---|---|---|---|
| QNX001 | high | documented | events | **epoll event loop.** Use poll()/ppoll()/select() when you only wait on file descriptors. Use ionotify() with a SIGEV_PULSE event (registered with MsgRegisterEvent()) and receive it with MsgReceivePulse() when the loop must also serve QNX messages, timers or pulses from other threads. ionotify() arms are one-shot: re-arm after every delivery. |
| QNX002 | high | verify | events | **eventfd wake-up primitive.** To wake a poll()/select() loop from another thread use a pipe() (documented). In a channel/pulse design send a pulse to the loop's channel with MsgSendPulse() instead of an fd write. |
| QNX003 | high | documented | events | **timerfd timers.** Create a POSIX timer with timer_create() and a SIGEV_PULSE event, arm it with timer_settime(), and receive the pulse with MsgReceivePulse() in the same loop. timer_create() accepts CLOCK_REALTIME, CLOCK_MONOTONIC and CLOCK_SOFTTIME. Alternatively derive the poll() timeout from your next deadline. |
| QNX004 | high | verify | events | **signalfd signal delivery.** Block the signals and collect them with sigwaitinfo()/sigtimedwait() in a dedicated thread, which then wakes the main loop (pipe write or MsgSendPulse()). For timer expiry prefer SIGEV_PULSE directly. |
| QNX005 | medium | documented | events | **inotify filesystem watches.** Keep the inotify code, add -lfsnotify to the link line, make sure fsevmgr runs on the target, and handle inotify_init() failure at start-up. Check event coverage per filesystem on your target (verify). inotify_qnx_ext() enables QNX-specific extensions. |
| QNX006 | high | verify | events | **fanotify.** Evaluate whether the documented inotify interface (served by fsevmgr) covers the use case; otherwise a QNX resource manager or filesystem-level hook is needed. No documented one-to-one equivalent: verify. |
| QNX007 | high | verify | process | **prctl().** PR_SET_NAME / PR_GET_NAME map to pthread_setname_np(0, name) / pthread_getname_np() (documented; the length limit is _NTO_THREAD_NAME_MAX instead of Linux's 16 bytes). Other options (PR_SET_PDEATHSIG, PR_SET_DUMPABLE, PR_SET_NO_NEW_PRIVS, PR_SET_SECCOMP ...) have no documented single-call equivalent: verify, or use procmgr_ability() for privilege control. |
| QNX008 | high | documented | process | **CPU affinity.** For the calling thread use ThreadCtl(_NTO_TCTL_RUNMASK, &mask) (also _NTO_TCTL_RUNMASK_GET_AND_SET and _NTO_TCTL_RUNMASK_GET_AND_SET_INHERIT); map CPU numbers to bits of the runmask. The ThreadCtl() page says the runmask commands can only be executed on the calling thread, so code that sets the affinity of ANOTHER thread or process (sched_setaffinity(pid, ...)) has no documented equivalent: the target thread must set its own runmask (verify). sched_getcpu() has no documented equivalent: verify. |
| QNX009 | high | verify | io | **zero-copy transfer (sendfile/splice/tee).** Fall back to a read()/write() loop (or mmap() of the source file). Keep the Linux path behind an #ifdef and add a portable copy loop. Check your SDP for any BSD-style sendfile() before relying on it (verify). |
| QNX010 | medium | verify | io | **getrandom / getentropy / arc4random.** Read from /dev/random (or /dev/urandom) with open()/read(). On QNX these are provided by the 'random' service, which needs slogger2 running and must be started by root or with the right abilities; handle short reads and open failure. Check your SDP headers before assuming getentropy() exists (verify). |
| QNX011 | medium | documented | io | **memfd_create.** Use shm_open(SHM_ANON, O_RDWR, mode) for an anonymous shared-memory object (documented: passing SHM_ANON as the name sets O_ANON and O_CREAT), then ftruncate() and mmap(). Sealing (F_ADD_SEALS) has no documented equivalent: verify. |
| QNX012 | high | verify | system | **sysinfo / load / CPU count helpers.** sysconf() is documented for configurable limits (page size, open files, ...). For CPU count, memory totals and uptime check which sysconf names your SDP defines and the system page (<sys/syspage.h>); there is no documented load-average call (verify). |
| QNX013 | high | verify | system | **/proc paths (Linux layout).** Use the QNX /proc interface (devctl() with DCMD_PROC_* commands) described in the Programmer's Guide, sysconf(), or pidin-style queries instead of parsing Linux files. For the executable path, QNX provides /proc/self/exefile (verify on your target). |
| QNX014 | high | verify | system | **/sys (sysfs) paths.** Use the QNX driver/resource-manager interface for the device (GPIO, I2C, SPI, networking APIs, ...). Which one depends on your BSP: verify in the BSP documentation. |
| QNX015 | medium | documented | io | **/dev/shm shared memory.** Call shm_open()/shm_unlink() and do not hard-code the filesystem path. |
| QNX016 | high | documented | io | **/dev/mem physical memory access.** Use mmap_device_memory(). The process needs the PROCMGR_AID_MEM_PHYS ability (see procmgr_ability()); the correct physical addresses come from your BSP. |
| QNX017 | high | verify | headers | **linux/ kernel UAPI headers.** Identify the device or service behind the header and use the matching QNX interface (resource manager devctl()/ioctl() commands, Screen, QNX Sound Architecture, hw/ headers of the BSP). The right header is device specific: verify in the BSP/SDK docs. |
| QNX018 | medium | verify | io | **Linux-specific ioctl requests.** QNX resource managers are usually controlled with devctl() and DCMD_* commands. Map each request to the corresponding resource-manager command for your driver (verify per driver). |
| QNX019 | medium | verify | portability | **Linux/glibc preprocessor guards.** Add an explicit __QNXNTO__ (and/or __QNX__) branch, or restructure so the portable code path is the default. qcc predefines the QNX macros: confirm with 'qcc -V... -dM -E - < /dev/null' on your SDP (verify). |
| QNX020 | medium | verify | portability | **glibc / GNU extensions.** Provide a small portable replacement in your own code (strchrnul/memrchr/qsort_r/secure_getenv/canonicalize_file_name/get_current_dir_name are a few lines each), or guard the use. Do not assume the glibc behaviour (verify). |
| QNX021 | medium | documented | process | **non-portable pthread extensions.** pthread_yield() -> sched_yield() (documented). For timed joins, join from a helper thread or use a condition variable with pthread_cond_timedwait(). pthread_getattr_np: verify. pthread_setname_np()/pthread_getname_np() exist on QNX 8.0 with the same names. |
| QNX022 | high | documented | process | **raw syscall() / SYS_* numbers.** Call the libc/QNX API instead. syscall(SYS_gettid) -> gettid() (documented, <process.h>). Others: find the libc function, or QNX kernel call, that provides the feature. |
| QNX023 | medium | verify | io | **accept4 / dup3 / SOCK_* creation flags.** Use accept()/dup2()/socket() followed by fcntl(fd, F_SETFD, FD_CLOEXEC) and fcntl(fd, F_SETFL, O_NONBLOCK) (a small wrapper keeps the call sites clean). Note the non-atomic window if you fork concurrently (verify). pipe2() and mkostemp() are documented and can stay. |
| QNX024 | medium | documented | io | **Linux file-sync and allocation extensions.** fallocate() -> posix_fallocate() (documented); sync_file_range()/syncfs() -> fdatasync()/fsync()/sync() (documented where listed in the C Library Reference); readahead() -> posix_fadvise() (documented) or drop. |
| QNX025 | medium | documented | io | **statfs / sys/vfs.h.** Use statvfs()/fstatvfs() (documented, <sys/statvfs.h>); map the fields (f_bsize, f_blocks, f_bavail, ...). |
| QNX026 | medium | verify | time | **Linux-only clock IDs.** Use CLOCK_MONOTONIC for intervals and CLOCK_REALTIME for wall time. If you need time-since-boot semantics, decide what to do while suspended (verify behaviour on your target). timer_create() additionally accepts CLOCK_SOFTTIME. |
| QNX027 | medium | verify | io | **Linux-only mmap/madvise options.** Use MAP_ANON, drop prefault/huge-page flags (or find the QNX equivalent in the mmap() page), and replace mremap() with mmap + copy. madvise() has no C Library Reference page: use posix_madvise() (documented) (verify). |
| QNX028 | medium | verify | io | **Linux-only open() flags.** Use a mkstemp()+unlink() sequence for O_TMPFILE, drop O_NOATIME, and decide per filesystem about O_DIRECT. Verify each flag is defined in your SDP <fcntl.h>. |
| QNX029 | high | documented | security | **Linux capabilities.** Use procmgr_ability() to grant/lock abilities (for example PROCMGR_AID_MEM_PHYS, PROCMGR_AID_SPAWN_SETUID, PROCMGR_AID_XPROCESS_ABLE, as listed on that page). Decide per capability which ability you need. |
| QNX030 | high | verify | security | **containers, namespaces and seccomp.** There is no one-to-one mapping. Isolation on QNX is built from process abilities, the security policy and separate process managers/partitions: design the equivalent and verify against the QNX System Security Guide. |
| QNX031 | high | verify | security | **ptrace.** QNX debugging/inspection goes through the /proc interface (devctl() DCMD_PROC_* commands) described in the Programmer's Guide; PTRACE_* requests must be mapped individually (verify). |
| QNX032 | low | documented | process | **Linux scheduling policies and RT priority ranges.** Query the range at run time with sched_get_priority_min()/sched_get_priority_max() and choose priorities explicitly for the QNX system design; sched_setscheduler(), pthread_setschedparam() and pthread_setschedprio() are documented. |
| QNX033 | medium | documented | events | **SIGEV_THREAD_ID.** Use SIGEV_SIGNAL_THREAD (a QNX event type that signals a specific thread; which thread depends on the context, read the sigevent page) or SIGEV_PULSE. |
| QNX034 | medium | verify | network | **Linux socket options and netlink.** Check each option in the QNX 8.0 networking documentation / your SDP <netinet/tcp.h>; BSD-style alternatives (for example TCP_NOPUSH for corking, routing sockets instead of netlink) are likely but must be verified. |
| QNX035 | high | verify | system | **systemd / udev integration.** Replace service notification and device hotplug with the QNX equivalents for your system: process start-up via your boot scripts or system launch manager, procmgr_daemon() for daemonizing (documented) and QNX device managers. Make the dependency optional (verify design). |
| QNX036 | medium | verify | io | **ALSA audio.** QNX provides its own audio stack (QNX Sound Architecture) with an ALSA-like snd_pcm API; coverage differs from Linux ALSA, so check each call you use in the QNX audio documentation (verify). |
| QNX037 | medium | verify | security | **peer credentials on sockets.** For native QNX IPC the server obtains the client identity with iofunc_client_info_ext() in a resource manager. For UNIX-domain sockets check what your network stack documents (verify). |
| QNX101 | low | verify | build | **Linux link flags (-lrt -ldl -lpthread).** Drop the flags on QNX, or make them conditional so a missing library does not break the link (verify which stub libraries your SDP ships). |
| QNX102 | medium | verify | build | **host-architecture compiler flags.** Choose explicit target flags (for example -mcpu/-march values for your target board), or none. |
| QNX103 | medium | documented | build | **hard-coded host compiler.** Use qcc (C) / q++ (C++) and select the target with -V, for example qcc -Vgcc_ntoaarch64le or -Vgcc_ntox86_64. Generate a starter with: qnxport scaffold. |
| QNX104 | medium | verify | build | **OS detection that only knows Linux.** Add a QNX branch (CMake with a QNX toolchain reports CMAKE_SYSTEM_NAME = QNX; autoconf host triplets contain 'nto-qnx'): verify with your toolchain and your config.sub version. |
| QNX105 | low | verify | build | **sanitizers and Linux-only linker flags.** Make them conditional for the QNX target and test the link with your SDP (verify). |
| QNX150 | low | verify | build | **BSD sockets need -lsocket.** On QNX the socket API is normally provided by libsocket: add -lsocket to the link line (verify against the networking documentation for your SDP). |
| QNX151 | medium | documented | build | **inotify needs -lfsnotify.** Add -lfsnotify to the link line (documented on the inotify_init() page) and ensure fsevmgr runs on the target. |
